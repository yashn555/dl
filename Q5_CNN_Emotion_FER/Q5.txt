1. PROBLEM STATEMENT (PS)
----------------------------------------------------------------------
Build a Convolutional Neural Network that detects human emotions from
facial images (happy, sad, angry, etc.) using the FER-2013 dataset.

Task type : 7-class single-label image classification
Input     : 48 x 48 grayscale face crop
Output    : probability distribution over
            [angry, disgust, fear, happy, neutral, sad, surprise]
Dataset   : FER-2013 (Facial Expression Recognition 2013)

----------------------------------------------------------------------
2. DATASET FACTS
----------------------------------------------------------------------
Total images : 35,887 (all 48x48 grayscale JPEGs)
Official split: 28,709 training  /  3,589 PublicTest  /  3,589 PrivateTest
Folder layout used here (Kaggle "msambare/fer2013"):
    train/<emotion>/*.jpg   -> 28,709 images
    test/<emotion>/*.jpg    ->  7,178 images (Public + Private combined)

Training class distribution (full 28,709):
    angry     3,995
    disgust     436   <-- severe minority (~1.5%)
    fear      4,097
    happy     7,215   <-- majority (~25%)
    neutral   4,965
    sad       4,830
    surprise  3,171

This notebook further splits train into 90% train (25,839) and 10%
validation (2,870) with a fixed seed. The test folder is NEVER used for
training, early stopping, LR scheduling or checkpoint selection - it is
opened once at the end for the final report.

Important context: FER-2013 labels were collected by crowd-sourcing and
are noisy; human accuracy on this dataset is only about 65% (+/-5%).
Published state-of-the-art models reach roughly 73-76%. So a well-trained
CNN scoring ~60-65% is a GOOD result, not a broken one.

         MaxPooling2D()  12 -> 6  ;  Dropout(0.25)

Dense(256, use_bias=False) -> BN -> ReLU -> Dropout(0.5)

 - padding='same' keeps spatial size inside a block; pooling does the
   downsampling, so no information is lost at block edges.
 - Conv -> BN -> ReLU is the canonical order: BN normalises the pre-
   activation, keeping ReLU inputs centred (better gradient flow).

   the conv bias would be cancelled by BN's mean subtraction (redundant).

   training images.

6. MODEL THEORY
----------------------------------------------------------------------
6.1 Why a CNN for faces?
    Emotion lives in local spatial patterns: eyebrow angle, mouth
    curvature, eye openness. Convolution slides small learnable kernels
    over the image, so the same "smile corner" detector works anywhere
    (weight sharing + translation equivariance). Stacking blocks builds
    a hierarchy: edges -> facial parts -> expression configuration.
    A Dense net on raw pixels would need far more parameters and would
    not exploit spatial locality.

6.2 Convolution arithmetic
    Output channels = number of filters; each filter is K x K x C_in
    (+1 bias if used). Params = K*K*C_in*C_out.
    Example: 3x3, 64 -> 128 channels = 3*3*64*128 = 73,728 weights.
    padding='same' pads so H,W are preserved; 'valid' would shrink by 2.
    ReLU = max(0,x) introduces non-linearity without saturating positive
    gradients.

6.3 MaxPooling2D(2x2)
    Takes the max in each 2x2 window: halves H and W (48->24->12->6),
    cuts computation, and gives small translation invariance.

6.4 BatchNormalization (the key accuracy ingredient)
    Per channel, normalise activations to zero mean / unit variance
    using batch statistics, then rescale with learnable gamma, beta:
        y = gamma * (x - mu_B)/sqrt(var_B + eps) + beta
    At inference it uses moving averages collected during training.
    Benefits: stabilises/accelerates training, allows higher LR, reduces
    sensitivity to initialisation, acts as mild regularisation.
    Placed BEFORE ReLU (Conv -> BN -> ReLU) and paired with
    use_bias=False in the preceding conv (BN's beta replaces the bias).

6.5 Dropout
    During training, randomly zeroes a fraction p of activations and
    rescales the rest, preventing co-adaptation. p=0.25 after pooling
    blocks (light), p=0.5 before the classifier (strong, standard).
    Disabled automatically at validation/inference.

6.6 Data augmentation
    RandomFlip(horizontal), RandomRotation(0.1), RandomZoom(0.1) create
    label-preserving variants, effectively enlarging the dataset and
    reducing overfitting. They live INSIDE the model: GPU-accelerated,
    training-only, and still random every epoch despite dataset caching.
    No vertical flip / heavy distortion - those would destroy the
    geometry that defines an expression.

6.7 Class imbalance and class weights
    disgust has 436 images vs happy's 7,215 (16.5x). Unweighted training
    lets the model ignore disgust (it can score ~25% by guessing happy).
    compute_class_weight('balanced') gives
        w_c = N_total / (K * N_c)
    so each class contributes equally to the expected loss.
    Effect: disgust RECALL rises sharply, its PRECISION usually drops
    (more false positives) - the intended trade-off. Overall accuracy may
    dip slightly while MACRO F1 improves; macro F1 is the fairer metric
    on this dataset.

6.8 Loss and output
    softmax converts 7 logits to probabilities summing to 1.
    sparse_categorical_crossentropy = -log p(true class), accepting
    integer labels (no one-hot needed). Adam(1e-3) adapts per-parameter
    step sizes; ReduceLROnPlateau then refines with smaller steps.

6.9 Mixed precision (mixed_float16)
    Convolutions/matmuls run in FP16 on Tensor Cores (T4 = compute
    capability 7.5): ~2x throughput, ~half the activation memory.
    Master weights remain FP32; Keras wraps the optimizer with automatic
    loss scaling so tiny gradients do not underflow. The final softmax
    layer is pinned to dtype='float32' because exp/sum in FP16 can be
    numerically unstable.

6.10 tf.data pipeline
    cache()    : decode + resize once, then stream tensors from RAM
                 (huge win on Colab's 2 vCPUs).
    shuffle()  : applied AFTER cache so order still randomises each epoch.
    prefetch(AUTOTUNE) : prepares batch N+1 while the GPU trains on N.
    test_ds is created with shuffle=False so labels and predictions align.

6.11 Evaluation metrics
    Precision_c = TP/(TP+FP)  - purity of predictions for class c
    Recall_c    = TP/(TP+FN)  - coverage of real class-c samples
    F1_c        = harmonic mean of the two
    Macro avg   = unweighted mean over classes (treats disgust equally)
    Weighted avg= mean weighted by support
    Confusion matrix: rows actual, columns predicted; off-diagonal hot
    spots reveal WHICH emotions are confused.
    Accuracy alone is misleading under imbalance -> always report macro
    F1 and the confusion matrix alongside it.

8. VIVA QUESTIONS AND ANSWERS
----------------------------------------------------------------------
Q1. What does this project do?
    Classifies a 48x48 grayscale face crop into one of 7 emotions using
    a CNN trained on FER-2013, then reports accuracy, per-class metrics
    and a confusion matrix on a held-out test set.

Q2. Why a CNN rather than a fully connected network?
    Local receptive fields + weight sharing exploit spatial structure
    (eyes, mouth) with far fewer parameters, and give translation
    equivariance; stacking blocks learns a feature hierarchy.

Q3. Describe FER-2013.
    35,887 48x48 grayscale faces, 7 emotions; 28,709 train and 7,178
    test here. Crowd-sourced labels are noisy; disgust has only 436
    training images while happy has 7,215. Human accuracy ~65%.

Q4. Why grayscale and 48x48?
    That is the native dataset format; expression is carried by shape
    and shading more than colour, and small inputs keep training fast.

Q5. Why three splits instead of two?
    Validation drives early stopping, LR reduction and checkpoint
    selection; if the test set were used for those decisions the final
    number would be optimistically biased (test leakage). Here test is
    evaluated exactly once, at the end.

Q6. How many parameters does a conv layer have? Example.
    K*K*C_in*C_out (+C_out if bias). 3x3, 64->128 = 73,728 (no bias).

Q7. Why padding='same'?
    Preserves spatial size within a block so only pooling downsamples;
    avoids losing border information at every convolution.

Q8. What does MaxPooling do?
    Halves height/width by taking the max per 2x2 window: less compute,
    larger receptive field, small translation invariance.

Q9. Explain BatchNormalization and why it is placed before ReLU.
    Normalises each channel using batch statistics then rescales with
    learnable gamma/beta (moving averages at inference). Before ReLU it
    keeps pre-activations centred, stabilising gradients and allowing a
    higher learning rate; it is the single biggest accuracy booster in
    this architecture.

Q10. Why use_bias=False in convolutions followed by BN?
    BN subtracts the mean, cancelling any conv bias, and its beta
    provides the shift anyway - the bias would be a redundant parameter.

Q11. What is Dropout and why 0.25 / 0.5?
    Randomly zeroes activations during training to prevent
    co-adaptation. Light (0.25) after conv blocks to keep features,
    strong (0.5) before the dense classifier where overfitting risk is
    highest. Inactive at inference.

Q12. Why horizontal flip but not vertical?
    Emotion is preserved under mirroring; upside-down faces are not a
    realistic variation and would destroy the geometry the model needs.

Q13. How is class imbalance handled? Give the formula.
    class_weight='balanced': w_c = N/(K*N_c). disgust gets ~9-10x,
    happy ~0.57x, so rare emotions dominate the loss proportionally.
    Alternatives: oversampling, focal loss, or collecting more data.

Q14. What is the trade-off introduced by class weights?
    Rare-class recall improves, precision typically falls, overall
    accuracy may drop slightly - but macro F1 (the fair metric) improves.

Q15. Why sparse_categorical_crossentropy?
    Labels are integer ids, so no one-hot expansion is needed; it
    computes -log p(true class) and pairs correctly with softmax.

Q16. What is mixed precision and why is the output layer float32?
    FP16 compute + FP32 master weights with automatic loss scaling:
    ~2x faster on Tensor Cores, less VRAM. Softmax in FP16 can
    overflow/underflow, so the final Dense is pinned to float32.

Q17. Explain the three callbacks.
    ModelCheckpoint saves the best val_accuracy model; ReduceLROnPlateau
    halves LR after 4 stagnant val_loss epochs; EarlyStopping stops after
    12 stagnant epochs and restores the best weights.

Q18. Why is ~63% accuracy acceptable here?
    FER-2013 labels are noisy and expressions are genuinely ambiguous;
    humans score ~65% and published SOTA is ~73-76%. A small from-scratch
    CNN at 60-65% is close to the practical ceiling for this setup.

Q19. Which metric would you report and why?
    Macro F1 plus the confusion matrix (and accuracy for reference),
    because imbalance makes plain accuracy hide failure on disgust.

Q20. How do you read the confusion matrix? Which classes confuse?
    Rows = actual, columns = predicted; diagonal = correct. Typical
    errors: fear<->sad, angry<->disgust, fear<->surprise; happy and
    surprise are the most reliably recognised.

Q21. Why cache() before shuffle(), and why prefetch?
    Caching stores decoded tensors so JPEG decoding happens once;
    shuffling after the cache still randomises order every epoch;
    prefetch overlaps input preparation with GPU computation.

Q22. What does the first cell do and why?
    Checks for a CUDA GPU, enables memory growth, measures free VRAM via
    nvidia-smi and exits with clear instructions if requirements are not
    met - preventing a silent multi-hour CPU run or a mid-training OOM.

Q23. How would you push accuracy higher?
    Transfer learning (ResNet/EfficientNet on 96x96 or 224x224 RGB
    upscaled faces), attention modules, label smoothing, focal loss,
    test-time augmentation, ensembles, or cleaner/larger datasets
    (RAF-DB, AffectNet).

Q24. How is the trained model reused?
    keras.models.load_model('best_emotion_cnn.keras'); the saved model
    contains Rescaling, so predict on a (N,48,48,1) batch directly -
    exactly what predict_image() demonstrates for a single face crop.
